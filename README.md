# Git & GitHub Workshop

> Welcome to the Git & GitHub workshop!

If Git is completely new to you, don't worry — that's exactly what we're here for :)

This repository is where we'll put the things we learn during the hands-on session into practice. We'll go through the basics of Git and GitHub and get you comfortable with the workflow you'll eventually use while working on projects and with other people.

---

## What we'll be doing

During the hands-on session, you'll get to:

- Create and switch between branches
- Make changes to files
- Stage and commit your changes
- Push your branch to GitHub
- Open a Pull Request
- Review changes
- Merge your work

The repository is intentionally simple.

**The code isn't the point — the workflow is.**

---

## Git at a glance

Here's the basic workflow we'll be working with:

**Make changes → Stage → Commit → Push → Pull Request**

- **Stage** — Choose the changes you want to include
- **Commit** — Record those changes in your local Git history
- **Push** — Send your commits to the remote repository on GitHub
- **Pull** — Bring changes from the remote into your local branch
- **Branch** — Create a separate line of development to work on
- **Pull Request** — Ask others to review your changes before merging them

We'll be using the **VS Code interface** throughout the workshop, so you won't need to memorise any commands.

---

## A quick note about Pull Requests

For this workshop, you'll be working from your **own fork** of this repository.

When you open a Pull Request to the workshop repository, an automated check will make sure that the changes in your PR follow the workshop's rules.

For your PR to be accepted, make sure that everything you add or modify is inside your folder under:

```text
submissions/
└── your-name/
```

You can organise your folder however you like — nested folders and files are completely fine.

If the check passes, your PR will be **automatically merged**. If it doesn't, the PR won't be merged, so don't worry if you see a failed check — just take a look at what you changed and ask for help if you're stuck :)

---

## Don't worry if Git is new to you

Git can feel a little confusing when you first see it. That's normal.

Follow along, try things out, and **don't hesitate to ask for help** if you get stuck. We'd much rather you ask than sit there wondering why Git decided to do something weird :)

And yes, things will probably go wrong at some point. That's part of learning Git too.

---

## What's next?

You don't need to become a Git expert today.

As you move through your AIML journey and start working on bigger projects or collaborating with others, Git and GitHub will become much more useful.

For now, just get comfortable with the basics, experiment a little, and have fun with it.

You can also check out the [GitHub Student Developer Pack](https://education.github.com/pack) to see what tools and benefits are available to you as a student.

If you get stuck later, the [GitHub Docs](https://docs.github.com/) are always there — and so are your seniors :)
